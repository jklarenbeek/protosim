32Interface examples

Connect the existing locally built MCP server

# Replace the absolute path with the local checkout.
claude mcp add --transport stdio protosim -- \
  node /absolute/path/protosim/mcp-server/build/index.js

codex mcp add protosim -- \
  node /absolute/path/protosim/mcp-server/build/index.js

These commands register a stdio server; they do not implement the proposed tools. tsc writes build/index.js; it needs npm ci and npm run build in mcp-server/ first. 2.1 Without a build, the committed bundle mcp-server/dist/index.js starts with plain node and offers the same three tools; an installed package provides it as protosim-mcp (MC06). Either way the server looks for bin/protosim two directories above itself and then on the PATH. Resolve dependencies in the server environment by capability: Protosim for simulation, build tools for compilation, and avr-gdb for the proposed debugger. Hosted clients need access to that execution environment; a laptop-local path alone is insufficient. [S4, R6, R7]

2.1 With the server as it is, pass --uart0-out <file> among the flags of run_simulation: it is the only way to get the structured result until PS11 is fixed (MC05).
